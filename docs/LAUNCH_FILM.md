# Jam Deck — 发布片脚本 v1（草案，待 Jam 拍板）

对标 [Leonxlnx/claude-launchvideo](https://github.com/Leonxlnx/claude-launchvideo)（虚构产品 Tessel 的 33 秒发布片）：
画面由 Remotion 从代码生成、声音由 Python 合成、无素材库、无模板、全片一个接力物贯穿，
每个落点锁在 120 BPM 的拍子上。本脚本沿用这套工艺，但换一条属于 Jam Deck 的主线。

- 规格：**40.0 s / 1920×1080 / 60 fps / 2400 帧 / 120 BPM / 20 小节**（1 小节 = 2 s = 120 帧，1 拍 = 30 帧）
- 接力物：**一颗荧光绿点 `#b8ff3d`**，全片不离画面
- 语言：中文为主，字标与 `LOCAL FIRST` 保留英文

---

## 0. 一句话与核心矛盾

> **Jam Deck 是设计师的过程工作台。**

参考片的主线是一句负面陈述被反转（"doesn't fit." → "Everything fits."）。
Jam Deck 的负面陈述不是"装不下"，而是**过程会蒸发**：

设计师手里每天流过的东西——需求截图、参考图、Figma 导出、录屏、竞品网页、一句口头反馈、自己画的那三笔——
最后只有一个交付文件活下来。**做了什么留下了，怎么想的没留下。**
下次遇到同一个问题，得从零再想一遍。

- 开场 slam：**「过程丢了。」**
- 收尾 snap：**「过程留下了。」**
- lockup 副标（复用现有封面文案）：**让灵感从剪贴板流向知识库**
- 末帧角标：**LOCAL FIRST**

> 备选主线（若 A 不够狠）：B「只剩结果。」→「过程也留下了。」 C 英文版 "the process evaporates." → "nothing evaporates."

### 编剧决定（这条最重要）

**40 秒塞 7 个卖点会变成功能罗列，力量归零。** 参考片全程只讲一件事。
所以 6、7 不单独立幕：6 号只在画面里自然存在（翻牌在跳、唱臂落下、缝隙绿点在呼吸），
观众读到"这是个真东西"就够了；7 号压成第 4 幕最后一拍的一句话。

全片只讲一条因果链：

> **过程蒸发 → 被一张画布收住 → 结算成一张记录 → 长成一个数据库 → 而且在你自己的盘上。**

## 3. 逐幕分镜

### 第一幕 · 丢了 — 0:00–0:06（第 1–3 小节）

- **0:00.0（帧 0）** 满幅荧光绿 `#b8ff3d`。第 1 拍落下时，绿场以光圈方式收缩，
  在 12 帧内收进画面中心一颗 3px 绿点，底下露出 Jam Deck 的**低对比浅灰点阵纸面**。
- **0:00.5（帧 30）** 绿点开始"嗒"——每拍一次。六位 `HH:MM:SS` 翻牌**从这颗点里被抽出来**，
  数字按真实翻牌规则（只对变化的位翻，280 ms）开始走。这是全片第一次告诉观众"它是真的"。
- **0:01.5（帧 90）起** 素材乱雨。每半拍一件，从画面上缘以不同角度砸进来，每一件都落在**不同的地方**，
  彼此不认识：需求截图 / 参考图 / Figma 导出 PNG / 一段录屏的首帧 / 竞品网页卡片 / PDF 反馈 / 聊天记录里孤零零一句话 /
  剪贴板 Polaroid。密度逐拍加倍（1→2→4→6 件/拍）。
  **关键：约 1/3 的素材在落地后继续滑出画外，不再回来。** 这就是"丢了"的视觉论证——不是堆不下，是留不住。
- **0:04.5（帧 270）** 「**过程丢了。**」slam。
  借参考片修过的那条craft：**标题必须左右留边、光学居中，slam 起始尺寸接近终态**（不要从 300% 砸下来，
  那是廉价的），80 ms 内落定，带一次 2px 过冲。句号是一个墨点。
- **0:05.5（帧 330）** 全部素材连同标题一起向内塌缩回那颗绿点，30 帧完成。画面只剩点阵纸 + 一颗绿点。

音：翻牌 tick（本片的声音签名，见第 5 节）；素材落地是纸张接触声，逐拍变密；slam 是一次低频击 + 纸撕；塌缩是倒放的吸气。

### 第二幕 · 印记 — 0:06–0:10（第 4–5 小节）

- **0:06.0（帧 360，Drop 1）** 绿点炸出冲击波，把整幅画面刷成**墨色 `#1a1a1a`**。
  （暗场是刻意的：Jam Deck 是纸面优先的产品，这里短暂进暗，第三幕"开成产品"时画面翻回纸白——
  明暗翻转本身就是一个拍点，也顺手说明插件有明暗双主题。）
- **0:06.5–0:08.0** lockup 合成：绿点停在原位不动，**"Jam Deck" 字标从点的右侧滑出**
  （这正是现有封面 `jam-deck-promo-cover-360x200.png` 的真实构图，不是新设计）。
  下方 12 帧后浮出细体副标「本地副屏工作台」。
- **0:08.0–0:10.0** 镜头缓慢推进（dolly，不是 zoom），绿点继续每拍"嗒"一次。
  最后半小节副标先收回，字标随后收回到绿点背后，只剩点。

音：Drop 1 落在墨色泛出的第 1 帧；低频下潜 + 反向混响尾巴；翻牌 tick 穿过整段不停。

### 第三幕 · 一块画布 — 0:10–0:16（第 6–8 小节）

- **0:10.0（帧 600）** 绿点原地不动，墨色从中心向外**翻成纸白 + 点阵**。
  同一帧，字标的笔画重排成真实工作台网格：时钟 4×4、日历 4×4、待办 4×4、剪贴板 4×5、快捷方式 3×4、Canvas 5×5
  （按 README 记录的最小完整尺寸，不臆造布局）。组件从"字"张开成"格"。
  绿点飞进待办列表，成为第一条进行中任务前面的**状态点**——第一次身份转换。
- **0:10.5–0:13.0** 工作台自己活着：翻牌在走；唱臂落下、唱片开始转；剪贴板多出一张 Polaroid；
  鼠标靠近组件缝隙，**缝隙绿点浮现**，沿缝拖一下，两侧组件面积同步变化。不解说，只是发生。
- **0:13.0（帧 780）** 主动作：一把素材被**拖**进右侧 Canvas（拖拽是这个产品真正的输入手势，
  它没有命令行，不要给它发明一个）。每拍两件落位：图片边到边铺满、录屏节点出现播放态、
  网页节点真的在渲染、Markdown 笔记、Canvas 文本。
- **0:14.5（帧 870）** 两张图重叠超过较小节点面积的 50% → **自动吸附**，柔和多层阴影 + 轻微上浮，
  随后收拢为 200×150 文件夹壳体：SVG 底板在后、4 个真实代表成员（1 居中或双列 ±2°/±4.6° 轻旋）、
  半透磨砂前片在前、右下双凹槽。
- **0:15.5（帧 930）** 单击壳体：前片翻开 48°，成员卡片从各自真实位置依次散开（300 ms，18 ms 错峰，封顶 72 ms），
  周围无关节点在半透蒙版下向外让位、保留 20px 间距。定格半拍。

台词（0:13.0 起，一小节一行，衬在左侧列）：**全都放进来。**

音：拖拽是低沉的布料摩擦；每次落位一声短促纸响；吸附是"啪"的一声吸合；前片翻开是纸板开合；散开是四声错峰的轻响。

### 第四幕 · 过程 — 0:16–0:24（第 9–12 小节）

窗口沿侧栏缝裂开：左侧加宽成一列**只放字**的空间，右侧画布沿铰链转开、满幅潜入。
一小节落一句，每句配一个真实动作，句子在下一小节被下一句顶掉（不堆叠）：

| 小节 | 台词 | 画面动作（全部为真实实现） |

**0:23.5（帧 1410）** 画布沿铰链转回窗口，左侧文字列收窄归位。

音：一小节一次和弦推进；画笔是纸上沙沙；连线是一声细弦；放映翻页是 36px 位移配气压声；AI 那拍是一次上行铃音。

## 4. 视觉纪律（片子不能违反产品自己的设计规范）

`docs/VISUAL_DESIGN.md` 的规则**对这支片子同样生效**——一支违反自己规范的宣传片会被设计师一眼看穿：

- 荧光绿只用于**焦点、今天、活动任务点、完成量热度、缝隙圆点**。除第 0 帧那一次满幅绿场（作为"绿点的前身"，是刻意的一次性例外），全片不得出现大面积荧光底。
- 状态只用 2–4px 小圆点、细环、轻分隔、文字层级。**不许出现厚日期格、列表卡片墙、彩色胶囊标签。**
- 待办分类（工作 / 生活）放在标题**之前**，低对比文字前缀，不另起一行做彩标。
- 圆角只用七档令牌：`chip / control / surface / sm / md / lg / pill`。文件夹壳体前片、唱臂、叠纸是登记过的拟物例外。
- 标题色固定 `#5c5c5c`；标签比标题再弱一档。
- 组件只有一个主表面。不给字段套底色卡片。
- 滚动条：静止完全不可见——**片中任何镜头都不该出现常驻滚动条**，那是没接入规范的样子。
- 明暗：第二幕短暂进墨色是叙事需要；其余全片纸面优先。

## 5. 声音

沿用参考片的做法：**声音全部由 Python 从振荡器与噪声合成，读取与画面同一条时间线导出的 `out/cues.json`**，
每一次"嗒"、落地、吸附、划笔、吐纸都锁在它自己的那一帧上。不用采样库。

- 120 BPM，一小节一和弦，四和弦循环（IV – I/3 – vi – V），F 大调。
- **声音签名 = 分体翻牌（split-flap）的"嗒"**，不是参考片那种瑞士钟摆。它开片、穿过 lockup 保持、收片。
  理由：翻牌是 Jam Deck 唯一允许逐位动画的元素，它就是这个产品的节拍器。
- 三个器乐落点：Drop 1 = 0:06 墨色泛出；Drop 2 = 0:24 第一道马克笔笔触；解决 = 0:36「留下了。」
- 音效谱系（全部合成）：纸张接触 / 吸附啪、纸板开合（文件夹前片）、马克笔沙沙、机械键、热敏步进齿、
  打字轻响（按笔画数调音量）、唱臂落下的一声闷响。
- 母版 −14 LUFS 整体，真峰上限 −1 dBTP，**在 AAC 编码之后测**。
- 画面静音渲染，ffmpeg 混流；对轨脚本超过 1 ms 偏差直接让构建失败（Remotion 自带 AAC 混流会留约 2.5 帧编码器预热）。

## 6. 工程结构（对标参考片，但有一处优势）

**优势：Tessel 是虚构产品，UI 可以随便摆；Jam Deck 是真插件——`styles.css` 和真实类名可以直接搬进 Remotion。**
片中的组件不是"画出来的界面"，是真组件吃真令牌渲染的结果。这是这支片子最硬的一点，必须守住。

```
film/
  src/
    timeline.ts            唯一真相：六幕 + 全部锁拍 cue（60 fps / 120 BPM / 2400 帧）
    Launch.tsx             全片（幕序列 + 音轨）
    blur.ts, LaunchSub.tsx 快门与亚帧流
    brand/                 令牌（直接 import 仓库 styles.css 的 --jd-*）、绿点 + 字标 lockup
    deck/                  真实工作台组件 + 脱敏演示数据
    canvas/                Canvas 节点、文件夹壳体（复用 assets/jam-deck-folder-shell.svg）、笔迹层
    acts/                  Act1Lost … Act6Kept
    fx/                    rack focus、streaming ink、马克笔笔触、吐纸
  scripts/
    export-cues.ts         导出全部同步点给配乐
    soundtrack.py          配乐 + 音效合成器
    measure-speed.py       光流 → 每帧动态模糊采样数（相邻采样间距 ≤ 3px，240° 快门，最多 48 采样）
    accumulate.py          浮点平均亚帧 → 抖动 → 只量化一次
    check-sync.py          音画对齐校验，超 1 ms 构建失败
    render.sh              cues → 配乐 → 亚帧 → 累积 → 混流 → 校验
  video/
    jam-deck-launch.mp4
```

动态模糊按胶片的方式做：先渲一版锐利帧，用光流量出每帧运动量，按需给出 1–48 个亚帧，
在**浮点域**平均后只量化一次——在 Chromium 里合成会让每个采样都量化到 8bit，柔和渐变会长出等高线环、浅灰会偏色。

```bash
npm install
npm run studio          # 交互预览
npm run render          # 正片
npm run render:preview  # 跳过动态模糊，约 6 倍速
```

## 7. 三个必须你先拍板的点

1. **演示数据用真的还是脱敏的？**
   片里会出现你真实的待办标题、vault 路径、Figma 链接、归档 md 内容。
   我倾向做一套 `film/deck/demo-data.ts`（照 `data.example.json` 的路子），内容是设计师日常但完全虚构。
   用真数据更可信，但等于把你的工作内容公开发布——**这个只能你定。**

2. **40 秒 / 六幕，还是砍到 30 秒 / 四幕？**
   砍的话删第四幕的"连线"和"问它"两拍，AI 与放映不进片。
   我的判断：主线（丢了→收住→结算→成库）不能砍，第四幕的四拍可以压成两拍。

3. **要不要一版 9:16 竖切？**
   同一条 timeline 复用，重排安全框即可，但第三、六两幕的拉远调度要重做（横向 tessellate 在竖屏里不成立）。
   多约半天。
