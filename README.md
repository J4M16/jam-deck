# Jam Deck

Jam Deck 是 Obsidian 副屏工作台插件：时钟、日历、待办、剪贴板、快捷方式、音乐播放器与可实时编辑的内嵌 Canvas 工作区，内置 AI 对话助手（DeepSeek / 千问）。

## 安装

**方式 A —— Release 手动安装**

1. 前往 [Releases](https://github.com/J4M16/jam-deck/releases) 下载最新版的 `main.js`、`styles.css`、`manifest.json` 三个文件
2. 在 vault 目录下创建 `.obsidian/plugins/jam-deck/`（若不存在）
3. 把三个文件放入该目录
4. Obsidian 设置 → 第三方插件 → 刷新插件列表 → 启用 **Jam Deck**

**方式 B —— BRAT 安装（beta 体验）**

1. 安装社区插件 [BRAT](https://github.com/TfTHacker/obsidian42-brat)
2. BRAT 设置 → Add Beta plugin → 填入 `J4M16/jam-deck`
3. 启用后刷新插件列表即可

## 快速上手

1. 启用插件后，在命令面板（`Ctrl+P`）执行 **Jam Deck: 打开工作台**，或按插件设置的侧边栏图标打开
2. 点击工作台顶部的「添加组件」，加入时钟、待办、Canvas 工作区等
3. 需要 AI 对话时，点击工作台右下角的 **AI** 按钮；首次使用前先到插件设置页填写 API Key（见下）

## 配置 API Key

设置 → 第三方插件 → Jam Deck → AI 设置：

| Provider | Key 获取 | 端点（插件自动路由，无需填写） |
|---|---|---|
| 千问 | 阿里云[百炼](https://bailian.console.aliyun.com/)或 Token Plan 申请 | `sk-sp-` 前缀 → Token Plan 专属端点；`sk-` 前缀 → 百炼通用端点 |
| DeepSeek | [DeepSeek 开放平台](https://platform.deepseek.com/) | `api.deepseek.com`（固定） |

> 千问 key 前缀决定端点：**`sk-sp-` 开头的 key 必须配套 Token Plan 专属端点**，`sk-` 开头的通用 key 配套百炼端点——插件按前缀自动路由，混用会报 `401 Incorrect API key provided`。

## 音乐播放器

- 在“添加组件”中选择“音乐播放器”，即可读取 Windows 当前公开的系统媒体会话。
- 封面显示为旋转 CD，并带白色唱臂：确认播放后唱臂落下、唱片旋转；暂停、停止或无会话时抬起并停驻。
- 歌名和歌手位于唱片右侧；歌词、来源状态文字和收藏按钮已移除。音源改为右上角的小按钮，只列出当前真实存在的 QQ 音乐、网易云音乐或汽水音乐会话。
- 上一首、播放/暂停、下一首默认隐藏，鼠标进入组件或键盘焦点进入后出现；触摸设备可先轻触组件唤出。
- 进度条在播放器公开 `IsPlaybackPositionEnabled` 时可通过鼠标、触摸和键盘拖动；松手只发送一次 Seek，并等待系统返回的真实位置确认。不支持 Seek 的播放器或曲目保持只读。
- 如果已连接过受支持播放器，而它当前未运行，点击播放会启动上次连接的软件。启动目标只能来自插件内置的 QQ 音乐、网易云音乐、汽水音乐枚举，并通过 Windows 注册启动项验证；不会接收或执行设置中的路径、命令、参数或网址。启动软件不代表自动开始播放。
- 常规媒体轮询仍为播放可见 2 秒、暂停 5 秒、隐藏 15 秒；只有用户明确点击启动后的最长 12 秒内临时以 500ms 查找新会话，成功、超时或组件销毁后立即停止。
- 当前开发机已验证 QQ 音乐会话、歌曲信息、时长和控制能力读取；QQ 音乐当前测试曲目报告 `canSeek=false`，因此按真实能力保持只读。网易云音乐和汽水音乐是否可 Seek 取决于对应版本公开的 GSMTC 能力。

## 待办、分类与日历

- 手动创建待办改为点击日历日期：新建弹窗会自动填入该日为截止日期，取消不会留下空待办或附件。
- 待办支持“自动、工作、生活”分类。自动模式下，标题含完整 `【…】` 时归为工作，否则归为生活。
- 归档目标可在设置中自定义「文件 / 目录」两种形式（工作、生活各自独立），默认都是**文件模式**：
  - **文件模式**：归档到单个 Markdown（工作默认 `Work/工作.md`，生活默认 `Life/Daily.md`），按日期标题分节。
  - **目录模式**：归档到目录下按日期生成的 `YYYY-MM-DD.md`（工作默认 `Work/工作日记/`，生活默认 `Life/生活日记/`）。
- 两种模式都使用**统一简单块格式**（见下「归档格式」），工作/生活块内通过「分类」行区分。
- 详情图片栏支持直接粘贴图片；详情底部可保存、归档、恢复或删除。
- 日历固定显示过去一周、本周与未来两周；已完成/已归档数量以日期按钮的品牌绿色热度显示，1–5+ 项对应 20%–100%，进行中与逾期待办仍保留可点击状态点。剪贴板及外部图片/文字拖入待办的创建方式继续保留。

## 归档格式

归档内容由「日期标题 + 任务块」组成，工作与生活完全相同，仅「分类」行不同：

```markdown
# 2026年8月6日

%% jam-deck-life-task:任务ID:start:v1 %%
- [x] 任务标题
  - 分类：工作
  - 截止：2026-08-06
  - 说明：补充说明
  - 链接：[Figma](https://www.figma.com/file/xxx)
  - 图片：![[附件路径.png]]
%% jam-deck-life-task:任务ID:end:v1 %%
```

- **文件模式**：所有日期的任务块都写进同一个文件，按 `# YYYY年M月D日` 标题分节。
- **目录模式**：每个日期一个文件 `YYYY-MM-DD.md`，文件内同样以日期标题 + 任务块组织。
- 任务块以 Obsidian 隐藏注释 `%% jam-deck-life-task:<id>:start:v1 %%` / `...:end:v1 %%` 标记包裹，阅读与实时预览中不可见（纯代码定位用）；插件凭标记定位、更新与移除归档块；手工编辑块内内容安全，但请保留首尾标记。0.30.2 及以前写入的 `<!-- ... -->` 旧标记仍可读取、更新与移除，重写后自动升级为隐藏注释。

## 待办归档附件

- 归档待办时，Jam Deck 会以目标归档文件作为上下文，遵循 Obsidian 的附件目录设置保存图片。例如文件模式 `Work/工作.md` 附件设为 `./附件` 时，图片会进入 `Work/附件/`。
- 归档采用可重试流程：先复制并校验附件，再更新带任务 ID 的日记块，最后保存待办状态；保存确认前不会删除旧图片。
- 恢复待办不会把图片搬回任务临时目录；彻底删除归档也不会删除归档附件。
- 旧版（0.29 及更早）的 `section-v2` 四段式工作日记仍可读取、恢复与编辑，不会被新归档覆盖；历史源图片默认保留。

## 工作台编辑布局

- 当前排布记录为各类型组件的最小完整显示范围：时钟 4×4、音乐 2×4、日历 4×4、剪贴板 4×5、快捷方式 3×4、原生 Canvas 5×5、待办 4×4、Canvas 文件 3×4、浏览器 3×3。
- 组件任一方向窄于自身阈值时，正文折叠为居中的标题图标水印；点击水印恢复到该类型的阈值尺寸。
- 恢复时只补足低于阈值的宽度或高度，已足够大的方向保持现状；优先移动与下方/右侧组件的共享边界，让目标组件长回完整范围并压缩邻居。共享边界无法提供足够尺寸时才自动搬移冲突组件，并优先推挤占地面积最大的组件；未进入碰撞链的组件保持原位。无空间或保存失败时不会留下半完成布局。
- 编辑态和浏览态统一通过组件间距处的绿色圆点调整尺寸；右下角斜杠缩放手柄已移除。拖动更新按动画帧合并，跨过组件完整显示阈值时正文立即出现，不需要等松手。

- 编辑模式拖动组件时整块悬浮抬起，拖动过程不算碰撞。
- 鼠标下方的空白矩形能容纳组件原尺寸时可直接自由放置，并保持按下时的抓取位置；只有原尺寸放不下时才进入矩形填充或零缝推挤。
- 编辑态与非编辑态下，鼠标靠近组件交界节点都会出现小圆点，可沿缝拖动以统一调整两侧组件面积；十字交点可四向拖动。
- 单个组件真实右下角的绿色圆点只缩放该组件；右侧或底部边缘中段圆点才统一收缩整条边上的贴边组件。圆点跟随新的包围边缘，可反向拉回。
- 添加组件没有独立空位时，会按最小完整尺寸切入当前占地面积最大的可压缩组件旁边；只压缩该组件，不扰动其他布局。
- 编辑态拖动开始时 A 会收缩到最小尺寸（2×2）参与插入计算与悬浮预览。
- 鼠标悬停在 B/C 之间可容纳最小宽高的空隙时，会预绘绿色渐变描边矩形：纵缝按统一宽度填满，横缝按统一高度填满。松手按矩形尺寸插入。
- 没有后邻、要从 B 延伸到画布底部或右侧时，需按住 Shift 才会显示延伸矩形并允许填充。
- 两个组件之间没有空隙时，拖到交界附近即亮起两端绿色渐变：松手后以最小宽/高插入，后方组件优先整体下移或右移；已经贴到画布边缘时改为缩短宽度或高度让位。
- 两种提示都没有出现时松手会取消本次拖动。缩放手柄仍按原碰撞规则调整单组件尺寸。

## 时钟与倒计时

- 时间组件下方提供轻量倒计时：未运行时使用“时 : 分 : 秒”三格输入，勾选后立即开始，取消勾选即可停止。
- 运行中固定显示六位 `HH:MM:SS` 独立数字翻牌，使用中线、上下明暗和短翻转表达秒数变化；牌面会跟随 Jam Deck 明暗主题切换。倒计时采用绝对截止时间保存，工作台切页、组件重绘或 Obsidian 重启不会重置进度。
- Windows 下到点后通过 Windows Runtime Toast API，以 Obsidian 注册的 `md.obsidian` 应用身份发送系统通知；原生通道失败时回退为 Obsidian 内通知。Obsidian 完全退出期间不会驻留后台，重新启动后会立即结算已到期的倒计时。

## 快捷方式

- 原有快捷方式图标路径即使仍写着 `.png`、`.jpg` 或 `.jpeg`，只要同目录存在唯一同名 `.webp`，就会自动显示 WebP；单纯打开工作台不会改写个人数据，编辑并保存该快捷方式时才会写回新路径。
- 把剪贴板组件中的完整 `http / https` 链接拖进快捷方式组件，会立即创建网页快捷方式。名称取自域名，图标由域名首字或地球图标在本地稳定生成。
- 0.9.0 不访问网页、不抓取网页标题或 favicon，因此离线也能创建，且不会产生网站图标附件。
- 快捷方式可在同一个组件内直接拖拽重排；键盘聚焦卡片后可用 `Alt + 方向键` 前后移动，`Alt + Home / End` 移到首尾。
- 原有外部文件、应用和文件夹拖入继续保留。网页仅接受完整的 `http / https` 地址，普通说明文字不会被拆取成链接。

## Canvas 混合素材堆叠

- 内嵌 Canvas 网页节点打开默认浏览器后，Jam Deck 会在 Obsidian 窗口返回时受控重申可见宿主 leaf，恢复网页与 Canvas 首击交互；不会刷新网页、重建 Canvas 或主动抢走 iframe 输入焦点。若返回后先操作了其他日记或组件，本次恢复自动取消。
- 内嵌 Canvas 图片保持边到边显示，图片圆角与快捷方式图标统一为 10px；分组圆角同步使用 14px，文件名继续隐藏。
- 图片、Canvas 文本和 Markdown 笔记可一起堆叠。拖动合格节点时会以柔和阴影、轻微上浮和放大形成悬浮感；覆盖另一成员面积严格超过较小节点面积的 50% 后自动吸附。
- 拖入的图片或文本若明显大于目标组，会按目标现有图片、文本与笔记的平均 Canvas 尺寸等比缩小；已有成员不会连带改尺寸，节点也不会被放大。首次缩小前的 Canvas 尺寸会保留，安全拖出堆叠后围绕最终落点中心恢复。
- 单击堆叠会让图片、文本和笔记从真实位置依次展开；缩小过的图片与文本以原 Canvas 尺寸参与预览，排版按组件尺寸、内容比例和数量自动寻找紧凑行列。
- 展开时每一层图片都从自己在堆叠中的真实位置移出，收起时沿各自路径回到原位；动画期间底层真实节点会完全让位给移动副本，不会留下一张静止底图。
- 展开排版附近的其他节点会在半透明蒙版下向外推开，为焦点组合让出空间；图片、文本、Markdown 笔记、嵌套 Canvas 和网页卡片均参与，收起后回到原视觉位置。该位移不写入 Canvas 文件和撤销历史。
- 蒙版会拦截下面所有图片、Canvas 控件、鼠标和键盘操作；点击蒙版或按 `Esc` 仅收起预览，不会误选、复制或修改下面的节点。
- 单击与拖拽以 5px 移动阈值区分；只要进入拖拽便立即收起预览，松开不会误触发展开。
- 展开卡片是短生命周期副本：单击文本回到真实节点继续编辑，单击图片打开最大 90% 视口预览，单击 Markdown 笔记在新标签页打开；鼠标/笔拖动超过 6px（触控 10px）则可把该节点直接拖离堆叠。拖动途中不写文件，松手时才提交一次世界坐标更新。
- 展开文本使用固定的 12px 屏幕字号；Canvas 缩放与预览卡片自适应只改变排版尺寸，不再反向放大文字。
- 文本内边距同样固定为 16px，并清除克隆内容的居中阅读宽度；展开卡片不再统一套用圆角外壳。
- 纯展开与收起不修改真实节点位置、Canvas JSON 或历史；系统启用“减少动态效果”时自动取消位移动画但保留最终排版。
- 自动吸附与尺寸归一化复用 Obsidian Canvas 的移动与历史接口；位置、尺寸和 Jam Deck 可逆元数据会被同一次撤销/重做完整处理。

### Canvas 文件夹

- 手动拖动两个或以上支持的图片、Canvas 文本或 Markdown 笔记，使节点覆盖目标面积严格超过较小节点的 50%，会自动创建文件夹；已有显式文件夹不会与其他文件夹自动合并，旧的隐式堆叠仍由原堆叠预览处理。
- 在原生 Canvas 选中多个支持节点后，选中工具栏会出现“堆叠编组”和“网格排列”。“堆叠编组”创建同构文件夹并默认折叠；“网格排列”只整理所选节点，已有文件夹全选时会保留文件夹并切换到网格布局。
- 折叠文件夹严格按 Figma `NZS4 / 102:6` 的 200×150 壳体显示最多 4 个真实代表成员：完整 SVG 底板在后、代表图居中或双列轻旋转、半透磨砂前片在前，不使用额外遮罩；非代表成员隐藏但不会创建常驻克隆。拖动壳体会移动整个文件夹。
- 点击文件夹继续打开原有堆叠预览，不解散编组：前片先翻开、成员卡片散开；关闭时卡片先回位，再合拢前片。壳体只保留颜色圆钮，点击后在当前 Canvas leaf 展开 6 个低饱和色值；聚焦、拖出、Esc、空白点击及减少动态效果继续沿用旧预览交互与清理语义。
- 选中单个节点后，悬浮工具栏的聚焦改为放映：进入与文件夹点开大图相同的遮罩全屏，带关闭按钮；再按 `F`、`Esc` 或点击遮罩关闭。文本用纸面边距收紧排版；视频可用空格播放。独立节点若有连线，方向键沿连线翻页（左右连线用左右键，上下连线用上下键），有邻居的方向同时显示圆形箭头。文件夹展开仍用左右按成员顺序翻页。`F` 仅在该工具栏出现时打开。

## Canvas 画笔

- 点击内嵌 Canvas 底部工具栏的画笔按钮进入标注模式；工具栏和画笔面板采用大圆角底板、低对比边界与柔和多层阴影。
- 提供画笔、荧光笔、整笔擦除、4 种颜色、3 档固定粗细、撤销、重做和完成。鼠标与数位笔统一使用所选粗细，不读取压力或倾角。
- 按住 `Space` 可临时恢复 Canvas 平移，`Esc` 退出画笔模式；右键、滚轮和触控继续交给原生 Canvas。
- 笔迹保存在 Canvas 同目录的 `<文件名>.canvas.jam-deck.json` 伴随文件中，不修改原生 `.canvas` 内容。重命名 Canvas 时伴随文件同步迁移，删除时进入系统废纸篓。

## Canvas 当前节点发送给 AI

- 单选图片、文本、Markdown、链接或普通附件后，AI 按钮加入节点上方的原生选择工具栏；真实多选和堆叠预览期间保持隐藏。
- 图片作为视觉上下文发送；文本与 Markdown 发送正文，链接发送 URL，普通附件发送文件路径。AI 生成的文本可继续写回当前 Canvas。
- 同一个 Canvas 若已在 Obsidian 原生页面打开，Jam Deck 会安静销毁同路径的自有嵌入并停止在途图片导入，不调用原生页面的保存、关闭或布局接口；最后一个原生页面关闭后只恢复一次全新的嵌入实例。

## 项目边界

`D:\Project\JamDeck` 是唯一开发源。Vault 内的 `.obsidian/plugins/jam-deck` 只是 Obsidian 运行副本，不应直接修改。

个人状态保存在 Vault 插件目录的 `data.json`。该文件不属于项目，部署脚本不会读取、复制、删除或恢复它。仓库中的 `data.example.json` 仅用于说明数据结构。

## 开发流程

环境要求：Node.js 18 或更高版本，无需安装 npm 依赖。

```powershell
npm run verify
```

这会执行 JavaScript 语法检查和全部回归测试。

## 部署到 Obsidian

为避免 Obsidian 在三个插件文件替换期间读取到混合版本，请先执行以下任一操作：

1. 在社区插件中禁用 Jam Deck；或
2. 关闭 Obsidian。

然后运行：

```powershell
npm run deploy
```

部署脚本只处理 `main.js`、`styles.css`、`manifest.json`。它会：

- 校验项目和目标路径；
- 在目标同盘创建 staging；
- 备份当前三个运行文件；
- 部署并逐文件校验 SHA-256；
- 失败时恢复已经替换的文件；
- 成功后保留并输出备份目录。

部署完成后重新启用 Jam Deck 或重启 Obsidian。

自定义 Vault 目标：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/deploy.ps1 -TargetPluginDir "X:\Vault\.obsidian\plugins\jam-deck"
```

## 目录

- `main.js`：插件逻辑与视图。
- `styles.css`：Jam Deck UI 与明暗主题。
- `manifest.json`：Obsidian 插件清单。
- `tests/`：无依赖回归测试。
- `scripts/deploy.ps1`：受保护的 Vault 部署。
- `docs/`：架构、视觉规范和开发日志。
- `data.example.json`：脱敏配置示例，不参与运行。
